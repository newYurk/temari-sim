# Stage 2: план (визуализация и проверяемая модель одного образца)

Цель: пошаговая 3D-визуализация кику S8 из **рецепта**, где одна рабочая нить = один непрерывный материальный путь,
с проверками criteria.md. Архитектура строится так, чтобы закрыть швы, найденные в prior #112.

## 1. Архитектура (обязательные инварианты)

```
recipe.json ──► path builder ──► thread paths (u, E/X, over/under, ops) ──► mechanics (опц., по этапам) ──► render
   (операции)      (геометрия G1–G9)        ▲ единственный источник для всех ниже         (Ф0–Ф4, Т1–Т6)      (three.js)
```

1. **Рендер никогда не вход механики.** Меш строится из результата path builder (или механики), а не наоборот. [prior #112 шов 1]
2. **Одна рабочая нить — один материальный баланс.** Каждая нить (A, B) имеет id, u монотонна через все ряды; park/resume не создают и не теряют материал; resume начинается в X последнего стежка. Никаких «трёх резервуаров». [prior #112, #106]
3. **Последовательное (инкрементальное) шитьё.** Состояние после стежка k (включая уже уложенные ветви и их слои) — вход для стежка k+1. Никаких независимых окон; пересборка из причинного префикса рецепта. [prior #112 шов 3]
4. **Слои физики подключаются по очереди**, каждый со своей приёмкой и явными параметрами с неопределённостью (uncertainties.md P1–P8); без измерений — только режим «идеализация» с пометкой. Никаких визуальных коэффициентов под видом физики [prior #93].
5. Статусы результатов (как в prior): accepted / unresolved / rejected; числовой успех ≠ ремесленная приёмка.

## 4. Что нужно от владелицы / практики (дешёвые измерения)

1. Фото готового кику S8 (или GT14-типа) сверху и сбоку с линейкой — число рядов, s кончиков, ширина полосы (U1, U2, U5).
2. Динамометр: обычная затяжка и «ослабленная» (P3).
3. Капстанный тест μ нить-нить и нить-обмотка (P1, P2).
4. Микрометр: 1 нить и 2–4 скрещённые под грузами (P5).
5. Взвешивание нити до/после (M2).

## 5. Чего не делать

- Не подгонять ряды «до 10» уменьшением толщины или неподтверждённым сжатием [prior #106].
- Не переносить старый рендер/эвристики (stackBump, gatherUnderBite и т. п.) — код prior не читался и не используется.
- Не выдавать геодезическую модель за предсказание формы (она — одно из положений в конусе трения).
